# Task 18A — Relation complementarity / oracle audit

## 唯一问题

在完全冻结 Task05b 的条件下，不同关系是否对不同音频样本具有互补性？如果存在一个样本级关系选择器，其理论上限相对最佳固定关系还有多少空间？

## 冻结项

- 数据、标签、多标签评价、音频处理、CLAP、RotatE 与实体映射：Task05b 原样复用。
- Top-K=5、Top-M=3。
- 知识文本：`class_name, tail`。
- 聚合：scale=100 的联合证据数量归一化 LSE。
- 一跳；不使用 AAKV、新的两阶段融合、Top-P、动态 alpha、门控或二跳。

## 唯一变化

从冻结 RotatE 的 `relation_to_id` 读取全部关系。每次只允许一种关系产生知识证据，得到每一种单关系方法的逐样本排名。

## 输出解释

- `Frozen-iKnow-05b`：使用05b原有逐数据集关系集合重建；必须与05b逐样本排名完全一致。
- `Best-Fixed-Relation`：在整个测试集上事后挑出的最佳单关系，仅用于分析，不是可部署方法。
- `Relation-Oracle`：用真实标签为每条样本事后选择最佳关系，仅表示理论上限，不能作为正式方法或主表结果。
- `Oracle gap`：Oracle 与 Best-Fixed 的差距；它决定是否值得继续设计无标签自动关系选择器。

## 决策规则

- 若多数数据集 Oracle gap 很小，停止该方向。
- 若多个数据集有稳定且实质性的 Oracle gap，再进入18B，设计只依赖音频、候选类别和KG证据的无标签选择器。
- 本轮所有方法必须共享同一个确定性音频嵌入；与未固定裁剪的历史05b若不一致，单独报告为旧流程的可复现性问题。

## 可复现性修正（18A aligned）

旧05b没有冻结每条音频的随机裁剪，因此跨进程重跑时逐样本排名可能变化。对齐版严格复用任务12：主种子42，根据 `SHA256("42|" + audio_path)` 生成每条音频的固定seed；同时启用PyTorch确定性算法、禁用TF32和cuDNN benchmark。在同一次编码后让CLAP、冻结05b和全部单关系共享唯一音频嵌入。后续18B必须复用这一协议。旧05b的逐样本差异作为历史可复现性审计报告。
